# 筛选交互自检

管的是书单页（首页 `#view-list`）那排状态筛选按钮：
`全部` / `想读` / `在读` / `已读`（`#filters` 下，靠 `data-status` 区分，
状态值 `all` / `want` / `reading` / `finished`）。

**只验不改。** 发现不符合的条目，先报告「哪条不过 + 实测数字」，等确认后再改。

## 一、检查清单（逐条打勾，每条都要留实测证据）

| # | 检查什么 | 过线标准 | 证据形式 |
|---|---|---|---|
| 1 | 有结果 | 点某档后只剩该档的书，卡片数 = 该档书本数，该档按钮带 `is-active` | 迷你 DOM 断言 + 真实浏览器截图 |
| 2 | 无结果 | 该档没书时：`#filter-empty` 显示、文案为 `没有「X」的书。`、`#book-list` 隐藏 | 断言文案字符串 + 截图 |
| 3 | 清空恢复 | 从无结果点「看全部」→ 全部书回来、高亮回到「全部」、`#filter-empty` 重新隐藏 | 断言三态 + 截图 |
| 4 | 判定只看实测 | 每条结论都来自 `grep -c` / 断言返回值，不许写「应该没问题」 | 报告里贴出实际数字 |
| 5 | 按钮状态 | `.filter` 有 `:hover` 与 `:focus-visible` 两种态，焦点态不用裸 `:focus` | `grep` styles.css 命中行号 |
| 6 | 不静默失败 | 事件委托用 `closest('.filter')` 且 `if (!btn) return` 前不报错；存储读失败时页面不白屏 | 坏存储变体跑一遍 |
| 7 | 键盘可操作 | Tab 能移到每颗按钮、Enter/Space 能触发，聚焦时有可见焦点圈 | 人眼在页面上验（我无法替代） |
| 8 | 对比度 | 文字对底色 ≥ 4.5:1，按钮边界对底色 ≥ 3:1，用公式算出数值 | 贴出计算输出 |
| 9 | 窄屏不溢出 | 四颗按钮在窄屏不横向溢出 | 窄窗口截图 |

## 二、跑法

### 1. 行为层（迷你 DOM）

参考 `frontend-dom-smoke-test` 技能；把 `references/mini-dom.js` 拷到项目外临时目录，
写 `_filter_test.js`（下划线开头 = 临时文件，别提交）：

    node _filter_test.js

三个用例对应清单 1/2/3：造三本不同状态的书 → 点各档 → 断言卡片数与文案 →
点「看全部」→ 断言恢复。**每一步都要断言 `#filter-empty` 的 hidden 值**，
不能只看卡片数（Day 11 踩过：只测「有没有生效」会放过一半 bug）。

### 2. 渲染层（真实浏览器）

按 `frontend-dom-smoke-test` 的「无头浏览器」一节做探针页截图。
⚠️ 记得**先在探针里造数据**（`Store.addBook(...)`），否则新 profile 下书架是空的，
截出来是空状态，会被误判成「筛选坏了」。

### 3. 对比度

用 `frontend-design-review` 技能里的公式算，**不算不能说达标**。

## 三、坑（这份清单管的东西踩过的）

- **两种「空」要分开**：一本书都没有 → `#empty-state`（带「添加第一本书」）；
  有书但这档没有 → `#filter-empty`（带「看全部」）。查错容器会得到「0 条」的假象。
- **判定筛选生效别只看卡片数**，`#filter-empty` 的 `hidden` 才是真状态。
- **`state.filter` 是内存变量**，刷新页面会回到 `all`——这是设计如此，不用报错。
