## 一、念给对方听的任务

念完一条，等他做完再念下一条。**他问「在哪里」，你就回「你找找看」。**

1. 把你最近在读的一本书，记到这个网站里。
2. 打开这本书，把「读到第几页」改成一个随便的数。
3. 让书架只显示你「想读」的书。
4. 去「论坛」看看别人在讨论什么书，挑一本点进去看看。
5. 随便逛逛 —— 有没有哪里让你犹豫、找不到，或者觉得奇怪的？

**（他做完第 4 条后，补一句：「你随便刷新一下页面看看。」）**

## 六、测试结果

- 时间：19:34
- 被测者：朋友（第一次用这个项目）
- 设备：电脑（在线版）
- **对方卡住/犹豫的地方**：**保存进度** —— 输入页数、点「保存进度」后按钮毫无变化，以为没保存上
- 另一条反馈：刷新页面后要重新登录 —— **这不是 bug**，社区层（账号/私信/帖子）目前全在内存里做 mock、没有后端，刷新必然清空。后端接入后自然解决，本次不修
- **我（大帅）之前没发现的原因**：保存时下面那个百分比和进度条都会变，我以为用户都能注意到

### 为什么自己测不出来（今天的收获就在这）

反馈的位置和用户视线的位置**错位**了：我把反馈放在「结果」上（百分比、进度条），
而第一次用的人盯着「按钮」看 —— 他刚点的就是按钮，他在等按钮给回应。
自己测一万遍也测不到，因为我已经知道结果在哪，眼睛会自动往那儿看。

## 七、最小修复（Day 14 实施）

**只修一处**：点「保存进度」后，按钮自己给回应。

- 文字变「已保存 ✓」+ 按钮变成功色（白字对绿底实测 **6.55:1**，达标）
- 禁用 1.5 秒，顺带防重复提交；连续点会重置计时，不会卡在禁用态
- 回车键触发保存时同样有反馈（同一条代码路径）

**改动文件**：`app.js`（新增 `flashSaved()`）、`styles.css`（`.btn.is-saved`）
**验证**：回归 78 + 81 全过；真实浏览器截图确认按钮变绿、数据同步（88 / 200 页 · 44%）
