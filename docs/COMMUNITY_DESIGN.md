# 多用户社区 · 设计文档

> 版本：v1.0（Day 11 起，多用户社区方向）
> 状态：设计定稿，待后端打卡那天落地接口
> 配套：本文档是「阅读的海洋」从「个人记录本」升级为「公开阅读社区」的蓝图

---

## 0. 一句话定位

**「阅读的海洋」从「只属于我自己的阅读记录本」，升级为「一个公开的阅读社区」——用户可以注册账号，把自己正在读的书分享到论坛，写下感受，和其他读同一本书的人交流、私信。**

一句话：**围绕「书」的公开讨论场**，而不是围绕「人」的社交场。

---

## 1. 定位转变（为什么翻篇）

| | 旧定位（Day 3~10） | 新定位（Day 11 起） |
|---|---|---|
| 给谁用 | 只有我一个人 | 所有注册用户 |
| 数据可见性 | 私密，只自己看 | **全部公开**（大帅与普通用户一样） |
| 核心功能 | 书单 / 进度 / 笔记 | 论坛发帖 / 评论 / 热门排行 / 私信 |
| 是否社交 | 明确不做（永久边界） | **核心能力** |
| 技术 | 纯前端 + localStorage | 前端 + 后端 + 数据库 |

**为什么变**：大帅 Day 10 明确提出「希望别人也能用，我也能在手机上打开」，Day 11 进一步要求「注册账号、论坛分享、热门书籍、私信」。这意味着之前「无登录、单用户、不做社交」的边界是**本期 MVP 的范围**，不是终局。本文档把终局写清楚。

**保留不变的部分**：书单 / 阅读进度 / 读书笔记这三件事仍然有用，只是从「唯一的全部」变成「用户个人主页里的一部分」。

## 4. 账号体系

### 4.1 注册流程

```
用户填：账号名 + 密码 +（可选）头像
   │
   ├─ 校验账号名：非空 / 长度 2~20 / 只允许字母数字下划线中文
   ├─ 校验密码：长度 ≥ 6
   ├─ 查重：账号名是否已被占用
   │     └─ 已占用 → 明确提示「该账号名已被使用，无法注册」
   └─ 通过 → 建号 → 自动登录
```

**关键交互（大帅点名要求）**：账号名相同时**无法注册**，并**告诉用户该账号名已被使用**。这个校验要「即时」——用户输入账号名时/点注册时就要给出反馈，不能等提交后才报错。

### 4.2 安全要点

- **密码绝不存明文**：存 `passwordHash`（加盐哈希，如 bcrypt / argon2）。数据库泄露也不暴露原密码。
- 登录成功发**会话凭证**（token / session），后续请求带上它识别身份。
- 注册 / 登录接口要做**防刷**（限流、验证码可选），本期学习项目可先简化。

## 5. 论坛

### 5.1 发帖流程

```
点「发帖」→ 填书名（必填）→ 填作者（选填）
   │
   ├─ 书名/作者输入后，触发「自动补封面」
   │     └─ 调 Google Books API 按书名+作者查封面
   │           ├─ 命中 → 展示封面图，可点换一张
   │           └─ 未命中 / 网络失败 → 用「书名首字」占位封面
   └─ 写感受看法（正文，必填）→ 发布
```

### 5.2 列表 / 详情 / 评论

- **列表**：帖子流按时间倒序；每条显示封面 + 书名 + 作者 + 发帖人 + 摘要 + 评论数 + 时间。
- **详情**：点进帖子看全文 + 评论列表；底部有「发表看法」输入框。
- **评论**：登录后可评论；评论按时间正序（旧→新，像楼层）。

## 6. 热门书籍排行

### 6.1 定义

**「热门」= 讨论量最多**。一本书的讨论量 = **它的帖子数 + 这些帖子下的评论数**（即参与讨论的总人次）。

### 6.2 三档口径

| 档位 | 时间窗口 | 说明 |
|---|---|---|
| 今日热门 | 最近 24 小时 | 当天讨论最热 |
| 本周热门 | 最近 7 天 | 近一周讨论最热 |
| 本月热门 | 最近 30 天 | 近一月讨论最热 |

### 6.3 算法（初版，够用即可）

```
对时间窗口内的帖子：
  按书名分组（书名精确匹配；后续可加归一化，如去空格、去副标题）
  每组讨论量 = 帖子数 + 评论数
  按讨论量降序排序，取前 N（如 10 本）
```

> 后续可升级：引入「时间衰减」（越新的互动权重越高）、「去重归一化」（《三体》《三体Ⅰ》算同一本）。初版先跑通，不做过度设计。

### 6.4 展示

- 论坛首页顶部有「今日 / 本周 / 本月」三个 tab。
- 每个 tab 下是书籍排行榜（封面 + 书名 + 作者 + 讨论量），点进去看这本书的所有相关帖子。

## 7. 私信（一对一对话）

### 7.1 形态（大帅选定：微信式）

- **会话列表**：左侧显示「和谁聊过」，按最后一条消息时间倒序；未读的会话有红点。
- **对话窗口**：点进某个会话，显示双方消息流（自己靠右、对方靠左），底部输入框发消息。

### 7.2 入口

- 从帖子/评论里点某个用户 → 「私信 TA」。
- 顶栏「私信」图标进入会话列表。

### 7.3 规则

- 只有登录用户能私信。
- 一期只做「一对一」，不做群聊、不做已读回执（可留 readAt 字段备用）。

## 8. 内容审核机制（参考抖音 / 小红书）

> 大帅要求：参考抖音、小红书的审核机制设计。

### 8.1 分层审核（抖音/小红书的通用套路）

| 层 | 时机 | 做什么 | 实现方式 |
|---|---|---|---|
| **第一层：发布前机审** | 提交瞬间 | 敏感词过滤（违禁词、广告、联系方式）、异常频率检测 | 屏蔽词库 + 正则；命中即拦截，提示「内容含违规信息，请修改」 |
| **第二层：发布后抽检** | 发布后 | 高曝光内容、被举报多的内容进入人工/二次机审 | 管理员后台队列（学习项目可简化为「举报驱动」） |
| **第三层：用户举报** | 任何时候 | 帖子/评论旁有「举报」按钮，选理由提交 | 见 3.5 举报表；举报多的内容自动下架/隐藏 |
| **第四层：管理员处置** | 举报后 | 删除 / 隐藏 / 封号 | 管理员后台 |

### 8.2 本期（学习项目）落地范围

- **屏蔽词库**：内置一份基础敏感词表（政治、色情、暴力、广告、辱骂），发帖/评论/私信时校验，命中即拦截。
- **举报按钮**：每篇帖子、每条评论都有「举报」入口，选理由（广告 / 辱骂 / 色情 / 侵权 / 其他）提交。
- **举报处置**：同一条内容被举报 ≥ 3 次自动隐藏，等待管理员确认删除。
- **管理员**：大帅自己就是管理员（账号设 `isAdmin` 标记），可删任意帖子/评论、可封号。

> 说明：完整的人工审核团队、AI 审核模型是重资产，学习项目用「屏蔽词 + 举报 + 管理员」这套够用且可演示。

## 9. 封面自动补全（Google Books）

### 9.1 方案

- 数据源：**Google Books API**（大帅选定）。
- 调用时机：发帖输入书名（+作者）后。
- 接口：`https://www.googleapis.com/books/v1/volumes?q=书名+作者`，取返回结果第一项的 `volumeInfo.imageLinks.thumbnail`。

### 9.2 降级

| 情况 | 处理 |
|---|---|
| API 无结果 | 用「书名首字」占位封面（复用现有 cover 样式） |
| 网络失败 / 超时 | 同上，占位封面 + 提示「封面加载失败，可稍后重试」 |
| 结果不准 | 给「换一张」按钮，取下一项结果 |

### 9.3 注意事项

- **国内访问 Google Books 不稳定**（已知网络约束），所以**必须做降级**，不能让发帖卡死在等封面上。
- 本轮前端只做「占位封面 + 预留调用点」，真接 API 等后端打卡那天（前端直接调 Google Books 也可以，但涉及 CORS 和墙，后端代理更稳——待后端打卡时定）。

## 10. 后端对接预留（接口清单）

> 本轮不写后端，但前端数据层会抽象成「调接口」的形态，后端就绪后只换实现。
> 接口命名先约定如下，后端打卡那天照此实现。

| 方法 | 路径 | 作用 | 返回 |
|---|---|---|---|
| POST | `/api/auth/register` | 注册（账号名+密码+头像） | 用户 + 会话凭证；账号名占用返回明确错误码 |
| POST | `/api/auth/login` | 登录 | 用户 + 会话凭证 |
| POST | `/api/auth/logout` | 退出 | ok |
| GET | `/api/me` | 当前登录用户信息 | 用户 |
| GET | `/api/posts` | 帖子列表（分页） | 帖子数组 |
| POST | `/api/posts` | 发帖 | 新帖子 |
| GET | `/api/posts/:id` | 帖子详情 | 帖子 + 评论 |
| POST | `/api/posts/:id/comments` | 评论 | 新评论 |
| GET | `/api/hot?range=day\|week\|month` | 热门书籍排行 | 排行数组 |
| GET | `/api/conversations` | 会话列表 | 会话数组 |
| GET | `/api/conversations/:id/messages` | 某会话消息 | 消息数组 |
| POST | `/api/conversations/:id/messages` | 发消息 | 新消息 |
| POST | `/api/reports` | 举报 | ok |

**错误码约定**（沿用现有 `{ok, error}` 中文提示风格）：

| 错误码 | 含义 |
|---|---|
| `USERNAME_TAKEN` | 账号名已被使用（注册时返回，前端据此提示） |
| `INVALID_CREDENTIALS` | 账号名或密码错误 |
| `UNAUTHORIZED` | 未登录 / 登录过期 |
| `CONTENT_BLOCKED` | 内容命中屏蔽词 |

## 11. 本轮前端落地边界（重要）

本轮**只做前端界面雏形 + 数据 mock**，明确**不做**：

- ❌ 真实后端 / 数据库 / 登录鉴权（等后端打卡）
- ❌ 真实的跨用户数据（mock 数据写死或存本地）
- ❌ 真实的 Google Books 调用（只做占位 + 预留调用点）
- ❌ 真实的举报后端处置（只做前端举报入口示意）

但**要为后端留好**：数据层抽象成接口调用形态、数据结构与本文档一致、错误码沿用约定。
