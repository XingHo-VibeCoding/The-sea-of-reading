# 阅读的海洋 · The sea of reading

> 一个帮你管好自己阅读记录的地方 —— 让你遨游在书籍的海洋里。

## 这是什么

一个纯前端的个人网站项目，用来存放自己的书单、阅读进度和读书笔记。

**它不提供任何书籍正文，也不做社交。** 只记录你自己产生的阅读数据。这条边界是经过需求研究后确定的，理由见 [`docs/research.md`](docs/research.md)。

项目目前处于**学习期**：一边按日程学 Git 和前端，一边把学到的东西落进这个仓库。Day 7 已经把三个 MVP 功能做出来了——打开就能用，怎么跑见下方[「本地运行」](#本地运行)。

## 本地运行

纯静态页面，**没有任何依赖，也不需要构建工具**。两种方式都能打开，选一种固定用就行。

### 方式一：直接双击（最省事）

在文件管理器里双击 `index.html`，浏览器会以 `file://` 的方式打开它，不需要启动任何服务。

**实测记录（2026-09-25，Windows 11 + Edge）**：双击打开 → 添加一本书 → 按 F5 刷新 → 书**还在**。

但这条路能用，是浏览器给的宽容，**不是标准给的保证**：`file://` 地址下 localStorage 属于**规范未定义行为**（MDN 的 localStorage 文档明确写了「不应依赖」），各浏览器做法不一致。所以：

- 本机现在可用，**换浏览器或换电脑就不一定**（Firefox / Safari 对 `file://` 更严格）
- **无痕 / 隐私窗口下一定存不住**，别在那里记东西
- 数据只在这台电脑的这个浏览器里，**清缓存、重装系统会丢**；重要的笔记自己另存一份

### 方式二：本地服务（更接近线上环境）

在项目目录下执行：

```bash
python -m http.server 8000
```

然后浏览器访问 <http://localhost:8000>。

也可以用 `npx serve`，但它需要联网下载工具，校园网环境下不一定顺利——上面的 Python 方式无需联网。

### 两种方式的存储是分开的

`file://` 和 `http://localhost:8000` 是**两个不同的来源**，浏览器各存一份数据，互相看不见。用方式一加的书，不会出现在方式二里——**这不是 bug**，是本来的规则。

> 提示：本地的数据库文件、环境配置不会进仓库，已被 `.gitignore` 挡住。

## 技术栈

原生三件套，**刻意不引入框架、构建工具和外部 CDN**（校园网 + 代理环境下，外部资源不可靠）：

- **HTML** —— `index.html`，单页三视图，靠 `hidden` 属性切换，不做页面跳转
- **CSS** —— `styles.css`，全部样式集中在这里；不用框架、不用 CDN 字体、不用图标库（图标一律用文字符号）
- **JavaScript** —— 分成两层：`store.js` 是**唯一**读写浏览器存储的地方，`app.js` 只管渲染和交互。两个普通 `<script>` 按顺序引入，**不用 ES 模块**（`file://` 下模块请求会被 CORS 拦掉，页面直接白屏）

数据存在**浏览器本地**（localStorage），只用两个键：`reading:books` 和 `reading:notes`。没有后端、没有数据库、不需要登录。

> 为什么这么选，以及第 23 天换成数据库时要动哪个文件，见 [`docs/TECH_DESIGN.md`](docs/TECH_DESIGN.md)。

工程方面：

- 版本控制用 **Git**，托管在 **GitHub**
- 推送走 **SSH over 443**（校园网封了 22 端口，已在 `~/.ssh/config` 配好转发）
